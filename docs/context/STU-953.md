# STU-953 — Text objects with auto-height

## Approved design

Full spec: `docs/superpowers/specs/2026-09-25-text-object-design.md`. Read it
first — this file carries only the contract, the checked facts and the traps.

In one line: a bare `text` element with user-set width and derived height, laid
out by a single pure module that both the canvas and the export call, so they
cannot wrap differently.

## Contract

```ts
// src/lib/text-layout.ts
export type Measure = (text: string, font: string) => number
export interface TextLayout { lines: string[]; height: number }

export function layoutText(
  text: string,
  maxWidth: number,
  opts: { fontSize: number; fontFamily?: FontFamily },
  measure: Measure
): TextLayout

export function cssFont(fontSize: number, fontFamily?: FontFamily): string
export function canvasMeasure(): Measure      // browser, memoised per font
export function estimateMeasure(): Measure    // average-glyph fallback
export const LINE_HEIGHT = 1.35
```

```ts
// src/types/whiteboard.ts
export interface TextElement extends BaseElement {
  type: 'text'
  text: string
  fontSize: number
  fontFamily?: FontFamily
  textAlign?: TextAlign
  textColor?: string
}
```

`textColor?: string` is also added to `StickyElement` and `ShapeElement`.
Undefined means `slate-800` on all three — exactly what they render today.

`height` is derived: `lines.length * fontSize * LINE_HEIGHT`, **no padding**.
It is stored on the element so every existing consumer keeps reading `.height`
unchanged.

New element defaults: `width` 240, `fontSize` 16, `textAlign` left, no
`textColor`.

## Verified repo facts

Each checked in this session. Do not trust a line here that has no location.

- `boardToSvg` runs in the browser — its only caller is `App.tsx:530`, feeding
  `svgToPngBlob`. This is what lets the canvas and the export share one real
  measurer.
- `wrapText` at `board-export.ts:76` is private to the export and estimates
  from an average glyph width; its own comment says "close enough for an
  export". **The canvas does not use it** — nothing outside `board-export.ts`
  references it. So the two already disagree about wrapping.
- `LINE_HEIGHT = 1.35` already exists at `board-export.ts:33`.
- Specs live in the top-level `test/` directory (45 files) and import from
  `../src/lib/…`. `src/lib/utils.test.ts` is the lone exception. E2E lives in
  `e2e/`.
- `test/` is **outside** the typecheck project — `tsconfig.app.json` includes
  only `src`. A spec can reference a prop that does not exist and
  `npm run typecheck` stays green. Filed as STU-926; rely on runtime output.
- The toolbar at 393px is 374px wide with 8 tools, 47px per tool, 42px buttons.
  A ninth overflows by 28px. Measured on the `chromium-mobile` project.
- `'frame'` is in `ElementType` and `FrameElement` is declared at
  `whiteboard.ts:51`, but nothing creates, renders or exports it. Dead type —
  leave it alone, it is out of scope.
- `e2e/fill-pattern.spec.ts` and `e2e/stack-order.spec.ts` both click the
  `Rectangle` or `Circle` tools by accessible name, so both break when the
  shape tools move behind a flyout.

## Assumptions

Phrased so an agent is invited to correct them rather than inherit them.

- **Verified:** Undo coalescing does not come from `useUndoRedo`, which does no coalescing
  at all — it only mirrors stack lengths into React state. Coalescing comes from
  `Y.UndoManager` at `src/lib/yjs-provider.ts:58`, which takes Yjs's default 500ms
  `captureTimeout`. Rapid patches within that window coalesce into one undo step. Writing
  `height` on each layout change is therefore safe.
- **Verified:** `textPaddingFor` in `element-style.ts` can return 0 for `text` without
  disturbing sticky or shape. Confirmed by reading its callers.

## Traps

Append the moment anything bites. Every later brief inherits this section.

- **`svg > rect`** (child combinator) is needed to reach a shape's painted
  body. A bare `rect` locator also matches the fill-pattern def's tile
  background, which sits earlier in document order.
- **jsdom does no layout and no CSS hit-testing.** Anything depending on
  pointer-events, z-order, overlap or measurement must be proven in a real
  browser. `test/setup.ts` carries a `PointerEvent` polyfill for this reason.
  This bites text measurement directly: `measureText` is meaningless in jsdom,
  which is exactly why `layoutText` takes an injected measurer.
- **Anything with parentheses or spaces in it is a style, not a class.**
  `pointer-events-stroke` and `filter drop-shadow(...)` as `className` generate
  no CSS. This repo has lost hours to it three separate times.
- **A live `.last()` locator re-resolves.** Pin a shape by
  `data-testid="shape-<id>"` in E2E, or drawing a second element silently
  re-points the first locator.
- **Toolbar buttons are `w-10` = 40px, not 42px.** An earlier claim of 42px in
  this ticket's dispatches was wrong. 40px clears WCAG 2.5.8 (AA, 24px) and
  sits 4px under 2.5.5 (AAA, 44px). Do not shrink them; do not repeat the
  wrong number.
- **A popup rendered before its trigger in the DOM breaks forward Tab**, even
  when CSS places it above. Tab order follows the DOM, so the open popup is
  reachable only by Shift+Tab and forward Tab abandons it. Render the popup
  after the trigger and move focus into it on open.
- **`aria-haspopup="true"` means "menu".** It is a lie over a `role="group"`
  popup. `aria-expanded` alone is the correct disclosure for one of those.
- **Throwaway specs are PLAYWRIGHT specs for VISUAL checks**, which cannot be
  asserted. Deleting a behavioural Vitest test because it was "scratch" is not
  the same convention and loses real coverage.
- **A freshly created empty text object has a 0x0 inner `text-body` div**, so
  Playwright refuses to double-click it — correctly, since it has no visible
  pixels. jsdom's `fireEvent.doubleClick` does not check visibility and
  dispatches anyway, so the jsdom test passes where a browser test times out.
  Target the OUTER container, which always has a real box because `drawnHeight`
  is `Math.max(layout.height, fontSize * LINE_HEIGHT)`. Real users are
  unaffected — the `onDoubleClick` handler is on that outer container.
- **Focusing an input from the same pointerdown that created it loses the
  race.** The canvas region is `tabIndex=0` for WCAG 2.1.1 arrow-key panning,
  so the browser's native default mousedown action refocuses it AFTER listeners
  run — stealing focus from the textarea and firing a spurious blur. With
  delete-on-blank-blur wired up, that deleted the object before the creating
  click finished: the tool was completely broken in a real browser and entirely
  green in jsdom. Defer the `focus()` one tick so the default action resolves
  first. jsdom dispatches no such default action, which is why it cannot see
  this class of bug at all.
- **A mutation-testing reviewer can die mid-mutation.** One was killed by a
  rate limit between mutating a file and restoring it, leaving the deliberate
  bug in the working tree. Always `git status` after a review dispatch, whether
  or not the report mentions a mutation — and when mutating, restore in the
  very next tool call rather than after further analysis.
- **The jsdom `getContext` stub must return `null`, not a usable fake.** A
  "more complete" fake 2D context silently swaps every test off the estimate
  measurer and breaks three pre-existing ones that deliberately depend on the
  fallback — `text-layout.test.ts`'s no-canvas block and `board-export.ts`'s
  anti-divergence test. The more thorough-looking fix is the wrong one.
- **`[data-testid^="text-"]` also matches `text-body` and `text-line`.** Same
  family as the earlier `/^text-/` bug, new shape: a prefix locator plus
  `.last()` silently re-resolves onto an inner line div once an object has
  content. Pin by the exact extracted id.
- **A wrap-forcing test string must be measured against the real loaded font**,
  not borrowed from another test. `Array(24).fill('wrap')` looked like it would
  discriminate two wrap widths and did not — in the app's real Inter font, 6
  and 7 words straddle ~250px, so both 220px and 240px land on the same side.
  `'text'` works because 7 is ~225px and 6 is ~192px. Measure, then choose.
- **`createSticky`'s trailing "click Select" is unsafe for text objects.** Text
  already resets to the Select tool on creation, so the extra click blurs the
  auto-focused textarea and deletes the still-empty object before the helper
  returns. Copying the sticky helper wholesale silently destroys what it made.
- **Local UI state must never derive from shared document data.** `TextItem`
  once initialised edit mode from `element.text === ''`, which meant every peer
  syncing a new empty text object opened and focused a textarea — and their next
  click deleted the creator's object and unsaved text. A creation signal is
  local; pass it as a prop from the tab that created the thing.
- **Panels open off the left edge** for elements near the left of the screen
  (STU-927, measured at x=-10). Do not fix it here; place elements where the
  panel lands on screen.

## Out of scope

- Rich text — bold or italic within one object.
- Routing sticky and shape labels through `layoutText`. It would fix the
  existing divergence, but it changes how every current board renders and
  deserves its own ticket and screenshots.
- The dead `frame` type.
- STU-927's panel clipping.
