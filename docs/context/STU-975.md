# STU-975 — More text sizes, up to 500px

## Approved design

`FONT_SIZES` becomes 17 values; `OptionList` gains a max-height derived from
`PANEL_ALLOWANCE`, with a test that the two agree. Bounded path, approved in
chat 2026-09-26. No spec file, no plan document.

## Contract

```ts
// src/lib/element-style.ts
export const FONT_SIZES = [
  12, 14, 16, 18, 20, 24, 28, 32, 40, 48, 64, 80, 96, 128, 200, 320, 500,
] as const
```

`OptionList` in `PropertiesBar.tsx` caps its height at `PANEL_ALLOWANCE` and
scrolls past it. The cap is **imported**, not retyped.

## Verified repo facts

Each checked in this session. Do not trust a line here with no location.

- `FONT_SIZES` is `[12, 14, 16, 20, 24, 32]` at `element-style.ts:28`. Note it
  has **no 18 and no 28** today — the new ramp adds them, so it is not purely
  additive at the top.
- `PANEL_ALLOWANCE = 160` at `context-bar.ts:22`, used at `context-bar.ts:94`:
  `above < VIEWPORT_MARGIN + PANEL_ALLOWANCE ? 'below' : 'above'`. It is the
  room reserved for a panel opening upward.
- `OptionList` at `PropertiesBar.tsx:119-129` renders
  `<div className="flex flex-col gap-0.5 min-w-[9.5rem]">` — **no max-height,
  no overflow handling**. 17 items at ~32px each is ~544px, about 3.4× what
  placement assumes.
- `OptionList` is shared: font family, font size, thickness and alignment all
  use it. The cap must not break the short ones.
- `DEFAULT_FONT_SIZES = { sticky: 16, shape: 14 }` at `element-style.ts:137`.
  Both survive in the new ramp, so no existing board shifts.

## Assumptions

- I believe ~32px per option is right for the height arithmetic, from the
  button padding in `OptionList`. **Measure it rather than trusting me** — the
  conclusion (a cap is required) holds at any plausible row height, but the
  exact overflow factor does not matter as much as the cap existing.

## Traps

- **jsdom does no layout.** A max-height and scrolling are CSS; jsdom will
  report the class is present and tell you nothing about whether the panel
  actually fits. Prove the 393px case in a real browser.
- **Anything with parentheses or spaces is a style, not a class.** A computed
  max-height must go through `style`, not `className` — Tailwind cannot
  generate a class from a runtime value.
- **Properties-bar panels clip off the left edge** (STU-927) and **the bar
  covers the top anchor** (STU-974). Both are out of scope and both live
  exactly here. Do not fix them; do not let a test depend on them.
- **`[data-testid^="text-"]` also matches `text-body` and `text-line`.**

## Out of scope

Growing an element to fit a larger font. STU-927. STU-974.
